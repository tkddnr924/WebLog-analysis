# 검증 기준

## 검증 진행 방식

기능 작업은 테스트 코드를 먼저 작성하고, 기능 구현 후 해당 테스트를 실행해 결과를 확인한다. 아래 시나리오 중 변경 범위에 해당하는 항목을 테스트 계획에 반영한다.

## 필수 정확성 시나리오
- Apache/Nginx Common·Combined, IIS W3C 헤더 변경, Custom, Unknown+인식 가능한 포맷.
- IPv4/IPv6, 요청 쿼리 문자열, 인용 문자열, 누락값, UTC 변환, 시간대 미확정.
- 빈 줄·주석·깨진 줄·CRLF/LF·BOM·인코딩 오류·긴 줄·gzip 손상.
- 미리보기와 실제 DB 결과 일치, 퍼즐/YAML 의미 보존, 재구성 표시 구분.
- 다른 위치의 동일 로그는 두 행, 동일 작업 재시도는 한 번만 저장.
- 원문/raw_line 테이블·실패 원문·샘플 영속 캐시가 없음을 검사한다. 예외 메시지에도 입력이 누출되지 않는지 확인한다.
- 파일 경로·줄 번호 추적, 원본 없는 조회·재구성, 원본 없는 재파싱의 명시적 실패.
- 접근 로그와 에러 로그가 각자 탭에서만 보이는지(작업의 `log_kind` 기준), 에러 행의 `extra_json`이 목록 조회에 실려 오는지, 확장 필드 조건(`CondField::Extra`)의 문자열 검색이 값 길이 상한을 지키는지.
- 스키마 v4로 올린 기존 저장소에서 프로필 이름이 `error_log*`인 작업이 error로, 나머지가 access로 채워지는지.
- 북마크가 파일·줄 기준이라 두 화면이 같은 표를 쓰는지(에러 화면에서 단 별이 유지되고 "북마크만" 조건에 걸린다).

## 통합·장애 시나리오
- 커밋 전후 취소와 강제 종료, 재개 후 중복·누락 검사.
- 실패행·주석을 포함한 체크포인트, gzip 재생, IIS 헤더 상태 복원.
- 파일 이동·변경·삭제, 디스크 부족, DB 쓰기 실패, 연결 중단.
- Appender flush와 트랜잭션 경계에서 실패를 주입해 레코드·체크포인트 원자성 확인.
- 가져오기 중 페이지 이동, NULL 시간, 같은 시간의 많은 로그, 필터 변경 시 오래된 응답 폐기.
- Windows 파일 선택·긴 경로·한글 경로·IPC·Tauri 번들 실행. 브라우저 모킹 테스트와 구분한다.

## 성능 실험
- GUI 없이 압축 읽기 → 파싱 → 저장 → 조회 경로를 먼저 만든다.
- 1GB → 10GB → 압축 후 100GB 이상으로 확장한다. 압축 전후 크기, 행 수, 데이터 분포를 따로 기록한다.
- 같은 줄 복사만으로 벤치마크하지 않는다. IP/경로/User-Agent의 다양한 고유값과 시간 순서가 섞인 자료를 포함한다.
- Windows x64/RAM 16GB/HDD를 기준으로 전체 프로세스 RSS, 처리량, DB 크기, WAL·임시 공간 최고치, 첫/다음 페이지 지연을 기록한다.
- 쿼리 세트: 시간 범위, 상태코드, IP, 경로, 시간 집계, 넓은 문자열 검색, 재구성 상세, 스트리밍 내보내기.
- 실행 계획과 cold/warm cache 조건을 구분한다. 무거운 작업 직렬화와 취소 응답도 확인한다.
- 실제 100GB 장비/데이터가 없으면 작은 실험만 수행하고 100GB 검증은 미실행으로 명시한다.

## 검사 명령

저장소 루트에서 로컬·CI 공통 진입점을 실행한다.

```bash
scripts/check.sh
```

```powershell
scripts\check.ps1
```

공통 스크립트는 `apps/desktop`에서 `pnpm install --frozen-lockfile`과 `pnpm check`(타입 검사·린트·관련 테스트·프로덕션 빌드)를 실행한 뒤 다음 Rust 검사를 실행한다. Tauri 컴파일에 필요한 프런트엔드 `dist`를 먼저 생성한다.

```bash
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
```

Windows x64 Tauri 빌드와 실제 파일 선택·IPC·DB 연동은 별도로 확인한다. 공통 검사 통과만으로 네이티브 동작이나 대용량 성능 검증을 대체하지 않는다. 실행 결과와 미검증 사항은 [검증 기록](verification.md), 측정 수치는 [벤치마크](benchmarks.md)에 남긴다.

## 개발 검사
- Cargo 포맷·Clippy·테스트와 React 타입·린트·테스트·빌드를 공통 진입점에 연결한다.
- Windows 실행 가능한 검사 스크립트를 제공한다. 명령과 도구체인 버전을 README에 기록한다.
- 의미 있는 동작·오류 테스트를 우선하고 커버리지 숫자만을 위해 구현을 그대로 복제한 테스트를 만들지 않는다.
