# 포맷 편집 명세

## 공통 모델
- schema_version이 있는 구조화된 정의 하나를 퍼즐과 YAML이 공유한다.
- 서버 힌트(Apache/Nginx/IIS/Unknown)와 실제 포맷(Common/Combined/W3C/Custom)을 분리한다. 같은 포맷을 여러 서버가 생성할 수 있다.
- 프로필의 표시 이름, 버전, 서버 힌트, 인코딩, 시간대 정책, 파싱 전략, 필드와 블록 목록을 정의한다.
- 블록은 literal, whitespace, field, optional_group, regex를 최소 모델로 검토한다. field는 이름, 타입, 추출 패턴, 누락값, 변환 규칙을 가진다.
- 미리보기와 가져오기는 정의를 동일한 Rust 실행 계획으로 컴파일해 사용한다.

## 전략
- Apache/Nginx 기본 프리셋은 공통·Combined를 제공한다. 요청문을 method/target/protocol로 구조화한다.
- IIS W3C는 #Fields에 따라 필드를 매핑하고 도중 헤더 변경을 반영한다. 무조건 고정 정규식으로 처리하지 않는다.
- Custom은 블록 조립과 고급 regex를 제공한다. Rust regex에서 지원하는 문법 범위를 UI에 표시한다.
- 정규식 일치 후 IP, 날짜, 정수 범위 등 의미 검증을 수행한다.
- 정규식 컴파일은 프로필별로 재사용한다. 패턴·줄 길이·샘플 수·편집 요청 실행량을 제한한다.

## 편집과 미리보기
- 원본 샘플은 파일에서 제한적으로 읽어 미리보기 메모리에만 유지한다. DB·브라우저 저장소·진단 로그에 복제하지 않는다.
- 일치 구간, 추출 필드, 오류 위치, 샘플 건수와 매칭률을 표시한다. 원문 미저장 정책이 미리보기 자체를 금지하는 것은 아니다.
- 잘못된 YAML/중복 필드/잘못된 참조는 적용하지 않는다. 초안과 마지막 유효 프로필을 구분한다.
- YAML 저장 후 재로드해 의미적으로 동일한 블록이 나오는지 검증한다. YAML 주석·공백까지 보존할 필요는 없다.
- 임의 정규식은 퍼즐에서 고급 블록으로 유지한다. 완전한 역변환을 요구하지 않는다.

## 재구성
- 저장 필드를 프로필의 표시 템플릿에 넣어 재구성한다. 템플릿이 없으면 필드 기반 표준 텍스트/YAML을 표시한다.
- 누락값은 정의된 표시 규칙을 따른다. 수집하지 않은 값을 추측하거나 만들어내지 않는다.
- 화면·내보내기에서 재구성 로그라고 명시하고 실제 원문 복원 기능으로 설명하지 않는다.

## 완료 기준
- 모든 기본 프리셋과 Custom 예제가 미리보기/저장에 동일 결과를 낸다.
- IIS 헤더 변경, 누락값, 인코딩 오류, 긴 줄, 잘못된 정규식에서 앱이 종료되지 않는다.
- 편집 후 재파싱은 명시적인 새 결과 버전이고 기존 데이터의 의미를 조용히 바꾸지 않는다.
