# 데이터 명세

논리 모델이다. 구체적인 SQL 타입·인덱스·배치 크기는 선행 실험으로 정하고 마이그레이션으로 관리한다.

## 저장 대상
| 테이블 | 주요 내용 |
|---|---|
| sources | source_id, 원래 경로, 현재 연결 경로, 파일 크기/수정 시각, 인코딩, 압축 방식, 선두 64KiB SHA-256, 전체 SHA-256(선택) |
| parser_profiles | profile_id, version, 정의 스냅샷, 정의 해시 |
| import_jobs | job_id, 결과 버전, 작업 상태, 프로필, 확정 건수, 시작/종료 시간, active(조회 대상 여부), replaces_job_id(재파싱 대체 대상) |
| import_job_sources | job_id, source_id, 처리 순서, 파일별 상태(pending/running/done/cancelled/failed) |
| import_batches | job_id, source_id, batch_id, 처리 시작/종료 위치, 다음 읽기 위치, 당시 헤더 상태, 성공/실패/제외 건수 |
| logs | 고유 키, job_id, source_id, batch_id, line_number, timestamp_utc, client_ip, method, request_target, protocol, status, bytes_sent, referrer, user_agent, 확장 필드 |
| parse_errors | job_id, source_id, batch_id, line_number, 오류 코드, 입력 문자열을 포함하지 않는 설명 |
| saved_views | 컬럼·필터·정렬 프리셋 |

원문 테이블/raw_line/원문 아카이브는 만들지 않는다. 파일 경로는 sources에 한 번 저장하고 행은 source_id로 참조한다. 포맷 버전은 작업/배치에서 참조하며 파일 중간의 헤더 변경도 추적한다.

## 출처와 재구성
- 줄 번호는 1부터 시작한다. gzip은 압축 해제된 스트림의 논리 줄 번호다.
- 일반 파일의 재개 체크포인트는 다음 줄 시작 바이트 오프셋이다. 줄 번호를 바이트 오프셋으로 간주하지 않는다.
- gzip의 논리 위치는 압축 파일의 seek 가능한 위치가 아니다. 초기에는 재생으로 디코더·헤더 상태를 복원한다.
- 저장 필드와 포맷 스냅샷으로 재구성 로그를 만든다. 공백, 인용·이스케이프 방식, 누락된 토큰, 인코딩을 원본대로 복원한다고 보장하지 않는다.
- 임의 정규식에 역변환 템플릿이 없으면 표준 필드 텍스트/YAML 표시로 대체한다.
- 파싱되지 않은 필드는 복원할 수 없다. 실패 행은 출처와 오류만 표시한다.
- 원본이 없어도 저장 결과 조회는 가능하다. 새로운 포맷으로 재파싱하려면 검증된 원본이 필요하다.
- 원본 재연결은 내용 검증을 거쳐야 한다. 샘플 해시·크기·시각만으로 파일 동일성을 보장하지 않는다. 강한 전체 검증 비용은 작업 상태에 드러내고 스트리밍으로 처리한다.

## 정규화
- 시간은 UTC, 시간대가 없으면 포맷에서 지정하거나 NULL/미확정으로 유지한다. PC 시간대로 조용히 해석하지 않는다.
- 원시 타임스탬프 문자열을 일괄 복제하지 않는다. 시간대 해석 정책은 포맷/배치에 기록한다.
- 누락값과 0을 구분한다. 바이트 수·응답 시간 단위를 명세에 고정한다.
- 요청 대상의 쿼리 문자열을 잃지 않는다. URL 디코딩은 별도 파생값으로 처리한다.
- 사용자 정의 필드는 확장 영역에 보존한다. 자주 검색하는 필드는 측정 후 타입 컬럼으로 승격한다.

## 원자성·복구
- 성공 로그·오류 메타데이터·배치 완료·체크포인트를 같은 DuckDB 연결의 명시적 트랜잭션에서 확정한다.
- Appender를 쓸 때 flush/close와 COMMIT 경계를 실제 API로 확인하고 장애 주입 테스트를 한다.
- 처리 구간은 주석·빈 줄·실패 줄을 포함한다. 성공 행만 세어 재개하지 않는다.
- 동일 작업/파일/배치 재실행의 중복을 방지한다. 동일 내용의 서로 다른 줄은 정상 로그다.
- 같은 파일을 다시 가져오는 요청은 기존 작업 재개 또는 명시적인 새 결과 버전으로 구분한다.
- 포맷 변경 재파싱은 새 결과 버전으로 수행한다. 기존 결과를 남겨둔 채 완료 후 전환하고 삭제는 명시적 작업으로 한다.
- 비정상 종료된 실행 작업은 interrupted로 복구한다. 파일·포맷 검증 후 마지막 커밋 위치 다음부터 재개한다.

## 조회 계약
- UI는 조건 객체를 보내고 Rust가 바인딩 SQL을 생성한다. 컬럼·정렬은 허용 목록으로 검증한다.
- 기본 페이지 커서는 필터/정렬 해시, 결과 버전, 확정 배치 경계, timestamp와 고유 키를 포함한다.
- NULL 시간은 별도 정렬 구간으로 명시한다. 이후 확정된 배치가 기존 페이지에 끼어들지 않도록 조회 범위를 고정한다.
- 내보내기에도 같은 범위 고정과 스트리밍을 적용한다.
