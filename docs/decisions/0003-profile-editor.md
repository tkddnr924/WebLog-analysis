# 0003. 퍼즐·YAML 편집기(4단계)

상태: 채택(2026-09-08).

## 1. 정의 하나, 표현 둘

- 기준은 Rust `FormatProfile`(schema_version 1)이다. 퍼즐 편집기는 이 구조를 그대로 편집하고, YAML은 serde로 같은 구조를 직렬화한 것이다. 둘 다 같은 정의 해시(FNV-1a)를 낸다. YAML 주석·공백은 보존하지 않는다.
- YAML 크레이트는 `serde_norway`(폐기된 serde_yaml의 유지 fork, 같은 API). 대안 `serde-saphyr`는 API가 달라 내부 태그 열거형 호환을 따로 검증해야 했다.
- 초안(draft)과 적용된 정의(applied)를 구분한다. 검증을 통과한 정의만 적용되고, 미리보기·가져오기는 적용된 정의를 쓴다. 잘못된 YAML이나 정의는 적용되지 않고 마지막 유효 정의가 유지된다.

## 2. 검증은 Rust가 한다

- `FormatProfile::validate()`가 경로가 붙은 문제 목록(`blocks[2].name` 등)을 돌려주고, 편집기는 그 경로로 입력 옆에 표시한다. 개별 검사를 통과하면 실제 컴파일(`CompiledBlocks::compile`)로 남은 문제를 잡는다.
- 필드 이름은 `[A-Za-z_][A-Za-z0-9_-]*`, 프로필 이름은 파일명으로 안전한 문자만 허용한다. strftime 패턴은 chrono `StrftimeItems`로 해석 가능한지 확인한다.
- 정규식 오류 메시지에는 사용자 패턴이 들어가지만 이는 로그 원문이 아니다.

## 3. 사용자 프리셋 저장소

- `ProfileLibrary`가 디렉터리 하나에 `<이름>.yaml`로 저장한다(임시 파일 후 rename). 내장 프리셋 이름은 거부한다. 앱은 `app_config_dir()/presets`를 쓰고 CLI는 파일 경로를 직접 받는다.
- 프로젝트 DB의 `parser_profiles`에는 가져오기 때 쓴 정의 스냅샷이 해시별로 남는다. 사용자 프리셋 파일을 지워도 기존 작업의 재구성과 재파싱 이력은 유지된다.

## 4. 정의 기반 재구성

- `reconstruct::from_profile`이 작업의 프로필 스냅샷을 읽어 블록 순서대로 텍스트를 만든다. 따옴표·대괄호 캡처는 구분 문자를 다시 붙이고, 누락값은 정의의 첫 `missing` 값(없으면 `-`)으로 표시한다.
- 선택 그룹은 안에 값이 있는 필드(또는 확장 필드에 남은 정규식 캡처)가 있을 때만 출력한다. 정규식 블록은 역변환 템플릿이 없어 `…`로 표시하고 `complete = false`로 알린다. W3C는 표준 텍스트로 대체한다.
- 화면은 어떤 프로필·버전·템플릿으로 재구성했는지 함께 보여준다.

## 5. 키보드 조작

- 블록 행은 포커스 가능하며 ↑/↓ 이동, Alt+↑/↓ 순서 바꾸기, Delete/Backspace 삭제, Enter로 뒤에 필드 추가를 지원한다. 입력란 안에서는 Alt+↑/↓만 가로챈다.
- 드래그 앤 드롭은 넣지 않았다. 버튼과 키보드로 같은 일을 할 수 있고, 접근성 검증 부담이 적다.

## 6. 남긴 것

- 임의 정규식을 퍼즐 블록으로 역변환하지 않는다(설계에서 합의). 정규식 블록은 고급 블록으로만 남는다.
- 인코딩 선택은 정의에 아직 없다(UTF-8 고정, 오류는 행 단위 실패). 명세의 "인코딩" 항목은 후속 범위다.
